# Data Quality Tests: Table Subject Area Assignment

This test suite validates the structural and naming features within your metadata datasets before training the Machine Learning model. The model’s objective is to automatically classify database tables into specific business domains or **Subject Areas** (e.g., *Finance, HR, Sales, Logistics*).

## 🎯 Why These Tests?

Subject Area classification relies heavily on textual metadata (naming conventions), schema structures, and relationship indicators (PKs and FKs). Since these features are generated automatically from active database schemas, several errors can compromise the training quality:

*   **Corrupted Text Strings:** Missing names, null text values, or incorrect length calculations distort text-based embeddings or string-matching features.
*   **Aggregated Feature Leakage:** Table-level summary stats (like `table_row_count` or `table_integer_column_count`) must be uniform for every single column belonging to that table. Divergent rows risk data leakage.
*   **Overlapping Key Targets:** In multi-task learning networks where keys are predicted alongside domains, a single column cannot logically serve as an individual key and a composite key component simultaneously.

These tests run as a strict quality gate in the automation pipeline to catch data degradation early.

## 📊 Test Suite Categories

The script executes comprehensive validations across **5 specific layers**:

### 1. Schema Validation ⭐⭐⭐
*   **`test_required_columns_present`**: Ensures all 41 structural, behavioral, string, and target features (including `pk_target`, `fk_target`, etc.) exist in the CSV. Prevents runtime training exceptions.

### 2. String & Metadata Integrity ⭐⭐⭐
*   **`test_naming_and_metadata_integrity`**: Validates the pillars of domain categorization:
    *   Confirms core text columns (`database`, `schema`, `table_name`, `column_name`, `column_type`) contain zero NULLs.
    *   Uses robust Pandas validation (`is_string_dtype`) to support both legacy object types and modern high-performance string engines (like PyArrow).
    *   Verifies that `name_length` perfectly aligns with the actual character length of the `column_name` string.

### 3. Logical Bounds & Binary Flags ⭐⭐
*   **`test_binary_flags_and_ratios`**: 
    *   Assures all categorical switch indicators (`name_ends_with_id`, `name_contains_key`, etc.) are bounded strictly to `0` or `1`.
    *   Guarantees all relational metrics (such as `null_ratio` or `unique_ratio_relative_to_max`) fall within the mathematical boundaries of `0.0` and `1.0`.

### 4. Table-Level Aggregation Consistency ⭐⭐⭐
*   **`test_table_level_consistency`**: Enforces strict grouping rules. Metrics summarizing an entire table (e.g., `table_unique_column_count`, `table_max_unique_ratio`) must display a variance of exactly 1 within the same table. This isolates individual features safely and protects validation loops.

### 5. Multi-Task Key Constraints ⭐⭐
*   **`test_target_relationship_constraints`**: Secures logical separation among target definitions:
    *   Validates that `pk_target`, `composite_pk_target`, `fk_target`, and `composite_fk_target` are strictly binary.
    *   Blocks logical overlaps (e.g., a column cannot be labeled as a standalone `pk_target=1` while simultaneously being flagged as part of a `composite_pk_target=1`).

## 🚀 Execution & Generic CSV Parameterization

The suite is parameterized to run against **any metadata CSV** generated by your pipeline. This is accomplished using a split architecture with a global CLI hook configuration.

### File Structure
Make sure both files reside in your test directory:
1. `conftest.py` — Hooks up the global `--csv-path` terminal parameter.
2. `test_training_data_quality_subject_area.py` — Contains the actual dataframe loader fixture and the test suite.

### Running the Tests

To test a specific data file exported from your pipeline, pass the relative path via the `--csv-path` option:

```bash
# Verify system dependencies
pip install pytest pandas

# Run tests targeting your raw metadata file
pytest test_training_data_quality_subject_area.py -v --csv-path="../../data/raw_metadata.csv"

# Run tests on the default backup file (raw.csv)
pytest test_training_data_quality_subject_area.py -v
```

### Strategic Trigger Points
1.  ✅ **Pre-Training Stage** – Local check before fine-tuning classification models.
2.  ✅ **CI/CD Integration** – Automated build barrier before pushing model artifacts to production.
3.  ✅ **Upstream Schema Drift** – Run immediately if metadata extractors encounter brand new databases.

## 🛠️ Common Errors & Troubleshooting

### ❌ `pytest: error: unrecognized arguments: --csv-path=...`
*   **Problem:** Pytest was called directly on the test file before loading the argument parser context.
*   **Solution:** Ensure the `conftest.py` file exists in the directory. If it exists and the error persists, invoke the directory generically (`pytest -v --csv-path="..."`) or ensure the file structure is untouched.

### ❌ `fixture 'df' not found`
*   **Problem:** The `df` fixture was accidentally moved or modified when refactoring.
*   **Solution:** Keep the `@pytest.fixture(scope="module") def df(csv_path):` function at the top of your `test_*.py` file. It reads the command line path from `conftest.py` and feeds the data to the assertions.

### ❌ `"Data anomaly: 'name_length' does not match the actual character count..."`
*   **Problem:** Feature transformation logic is out of sync, possibly caused by faulty string padding or encoding quirks.
*   **Solution:** Inspect the string-handling block inside your data preparation code to make sure string lengths are calculated after trim/strip adjustments.

### ❌ `"Data Leakage Risk: 'table_column_count' varies within the columns..."`
*   **Problem:** Severe aggregation error. Rows belonging to the same table display different structural counts.
*   **Solution:** Check the window function or `GROUP BY` statement in your feature factory query. Ensure that table-level aggregates do not accidentally slip across database or schema borders.
